# AceStream Playback Fix Plan

The user reports that AceStream broadcasts opened from the library are not displaying, even though the engine is running. Analysis shows that the current playback URL generated by the app (`getstream?id={hash}`) returns a 500 error on some engine versions (e.g., 3.2.8), while an alternative parameter (`getstream?infohash={hash}`) works correctly.

## User Review Required

> [!IMPORTANT]
> The fix involves changing how AceStream URLs are generated and handled. We will now attempt multiple URL variants (id, infohash, and cid) to ensure compatibility across different AceStream engine versions and stream types.

## Proposed Changes

### Core Media Components

#### [MODIFY] [AceEngine.cs](file:///C:/Users/Administrator/Downloads/streammesh/Core/Media/AceEngine.cs)
- Update `GetHttpUrlsWithTokenAsync` to return multiple URL variants (id, infohash, cid) instead of just one.
- Improve `OpenStreamAsync` to try alternative methods if `open_getstream` is not supported.
- Add a fallback mechanism to detect the best working URL by performing a lightweight HEAD request.

#### [MODIFY] [PlayerView.xaml.cs](file:///C:/Users/Administrator/Downloads/streammesh/UI/Views/PlayerView.xaml.cs)
- Update `LoadChannel` to try multiple AceStream URLs returned by the engine.
- Add better logging for AceStream initialization steps.
- Ensure the engine is "woken up" properly before passing the URL to the player.

### Network Components

#### [MODIFY] [MediaServer.cs](file:///C:/Users/Administrator/Downloads/streammesh/Core/Network/MediaServer.cs)
- Update `/api/ace/diagnostics` to include more detailed engine information (version, supported methods).
- Ensure the proxy endpoint handles AceStream redirects correctly.

## Verification Plan

### Automated Tests
- Since this is a WPF app, we will verify by checking the updated logs after the user attempts to play an AceStream link.
- Use `curl` to verify that the newly generated URLs (especially `infohash=`) return a 200 or 302 status instead of 500.

### Manual Verification
- Ask the user to try opening an AceStream link from the library and check if the video displays.
- Monitor the `app.log` for "AceStream playback sequence initiated" and subsequent "Flyleaf opening" logs.
